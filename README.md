# midi2jianpu

[![构建与回归测试](https://github.com/xueyuejue/midi2jianpu/actions/workflows/ci.yml/badge.svg)](https://github.com/xueyuejue/midi2jianpu/actions/workflows/ci.yml)

> 直接将 MIDI 文件转换为排版美观、可打印的中文简谱（数字谱）。

**在线试玩：[https://xueyuejue.github.io/midi2jianpu/](https://xueyuejue.github.io/midi2jianpu/)**（拖入 .mid 即转，零安装）

## 这是什么

`midi2jianpu` 是一个面向中文音乐人的开源工具：你手里的 `.mid` 文件——FL Studio 导出、电子琴/合成器录制、扒谱工程——丢进来，就能得到一份排版干净、可以直接打印或在手机上看的**中文简谱（数字谱）**。

### 与现有方案的区别

- 大多数简谱工具从 **MusicXML / 五线谱**倒推，而音乐人手里最多的文件其实是 **MIDI**；
- 现有脚本多是一次性转换器，输出格式杂乱、不能编辑、不能排版；
- 本项目目标是「丢入 MIDI → 干净简谱」一步到位，核心用 C++ 写成，零第三方依赖。

## 已实现

- [x] 解析标准 MIDI 文件（手写二进制解析，多轨、多通道、可变速度、SysEx 里的 GS/XG 鼓模式、Bank Select 的 XG 鼓组库与音色时间轴）
- [x] 自动识别调性（Krumhansl-Schmuckler 算法 + 终止音加权）
- [x] **五声音阶／民族调式**：宫、商、角、徵、羽自动判定**宫音**（简谱的 `1`）与调式。C 宫系统、终止在 G 的「G 徵调式」不再被 KS 误判成 `1=G`（整份谱子唱名全错）；页眉写 `1=C 大调 · G 徵调式（宫音 C）`，MusicXML 加调式文字标记。`--gong C` 手动指定宫音，`--no-pentatonic` 一键关掉。文件带 `0x59` 调号、七声旋律、偏音过多或宫音有歧义时**绝不介入**
- [x] **首调记谱**：小调记作 `1=关系大调`、主音落在 `6` 上（a 小调即 `1=C`），与简谱歌本一致
- [x] **时值量化**：把真实录音 MIDI 的 note-off 提前（门限时间）还原成标准时值，默认开启
- [x] 手动指定调性：`--key Em` / `--key Bb` / `--key f`
- [x] 移调功能：`--transpose +2`（半音偏移）
- [x] 识别拍号、速度（BPM）、调号、轨道名称、乐器名称、歌词、标记等元事件
- [x] **MIDI 内置歌词**：很多卡拉 OK `.mid` 用 `0x05 lyric meta` 自带逐字歌词，不用再另找 LRC，HTML / MusicXML / 网页版自动出词（含一字多音弧线）；`--no-midi-lyrics` 可忽略，网页上是同名复选框
- [x] 按拍号划分小节、输出小节线、HTML 自动换行排版
- [x] **弱起小节（anacrusis）**：`| 5 | 1' 7 6 5 |` 这种从弱拍进唱的曲子，第一小节天然不满拍。自动判定弱起长度后整条小节网格随之平移，小节线、重音、和弦、小节号全部归位；判错时用 `--pickup N` 手动指定拍数，`--no-pickup` 可关掉自动判定
- [x] 时值标注：全/二分/四分/八分/十六分/三十二分音符及附点，延长线 `-`
- [x] 同音延音合并（`1 1 1` → `1 - -`）
- [x] 多轨分离（优先用 MIDI 内置轨道名）
- [x] **打击乐轨自动跳过**：MIDI 通道 10 的音高是鼓件编号而不是音级，转成简谱只会得到 `1,, #4,,` 的垃圾，解析阶段直接丢弃并在谱面头部说明
- [x] **旋律轨智能判定**：按「歌词能否对齐 / 单音率 / 音域 / 音高丰富度」打分，不再拿「音符最多的轨」当旋律（那通常是鼓或柱式和弦伴奏）
- [x] 变速曲目：按 `set_tempo` 分段累积换算秒数，format 1 的 conductor 轨排在哪都不影响；页眉写成 `♩=120 → 90(第5小节)`，速度变化处的小节上另有 `♩=90` 标记
- [x] **中途变拍号**：`4/4 → 3/4 → 6/8` 这类曲子按拍号 map 逐段铺小节网格，文本 / HTML / MusicXML 的小节线、小节时长、和声窗全部跟着变；页眉写 `4/4 → 3/4(第3小节) → 6/8(第5小节)`，变化小节另有拍号标签，MusicXML 会重写 `<time>`
- [x] **中途转调**：`1=C → 1=D → 1=F` 这类副歌升调 / 桥段转调的曲子，按 `0x59` 调号 map 逐段重算首调唱名（同一个 MIDI 音高在不同段落数字不同）；页眉写完整转调链，变化小节标 `转 1=D`，MusicXML 重写 `<key>`，和弦名的等音写法（Bb / A#）也跟着调走。`--key` 手工指定时转调链整体平移，`--no-key-changes` 可忽略
- [x] 休止符 `0`（按时长显示时值线）
- [x] 高低八度点、升降号 `#`/`b`（降号调自动优先写 `b`）
- [x] **力度与演奏法**：CC11 力度（pp/p/mp/mf/f/ff，按通道隔离）、渐强渐弱、段落标记（`0x06`）、note-on 重音、弯音上滑/下滑/颤音、等间隔断奏，统一由 `ExpressionMap` 判定后同步写进文本 / HTML / MusicXML；`--no-dynamics` 一键关闭，网页是「力度与演奏法」复选框
- [x] **声部乐器标注**：解析层早已读取 `0xC0` 音色号却没落谱，现按轨主导通道查 GM 标准 128 音色名（常用音色附中文译名，如 长笛 / 钢琴 / 原声贝斯），谱面页眉与网页文件面板写出「声部：Vocal·长笛，Piano·钢琴，Bass·原声贝斯」；鼓轨（通道 10）不计入声部
- [x] **倚音（装饰音）识别**：MIDI 没有显式 grace note 事件，现从「极短前导音 + 紧邻长音」推断（前导音原始时长 < 1/8 拍、主音 ≥ 1/4 拍且≥4 倍、间隔在 [-1/8, 1/16] 拍内、异音高），判据按通道收紧，快速经过音 / 十六分音符流不误判；文本谱写成 `(装饰音数字)` 贴在主音前，HTML 用 `<span class='grace'>` 上标，MusicXML 写 `<grace/>` 不占时长
- [x] 三连音自动识别（按 1/3 拍体系判定时值，八分音符连奏不会被误判），且按 1/3、1/6、1/12 拍单独取档位——三连八分只画一条减时线，不会被时值表最近的 0.375 档误判成附点十六分（两条线加一个点）
- [x] 弯音轮修正（Pitch Bend 平均偏移 ±0.5 半音以上修正音高）
- [x] **和弦检测**：自动识别伴奏轨和弦进行（C/Am/G7 等 11 种类型）；按「和声窗」而不是整小节判定（4/4 半小节、6/8 附点四分、3/4 整小节），`| C  Am |` 这种一小节两个和弦能分别标出，相邻同名自动合并
- [x] **和弦转位与扩充**：同样三个音 C E G，E 在低音时是 `C/E`——音级集合完全相同，**转位只能由最低音判定**，低音落在和弦外（经过音 / 持续音）时则老实写 `C`，不硬凑斜杠；和弦类型在原有 9 种之外补上 `Bm7b5`（半减七）与 `G7sus4`（挂四七），文本 / HTML / MusicXML 三层同步
- [x] **渐快渐慢（rit./accel.）**：DAW 里的渐慢不是一条曲线，而是**几十个连续的 `set_tempo`**（每半拍一个自动化节点）。旧版把它们当独立变速逐条列进页眉——`♩=120 → 120(第3小节) → 116(第3小节) → …`，五条全指同一小节；HTML 每小节采样一次速度，满屏 ♩= 数字；MusicXML 反过来只在「节点正好落在小节线」时才写，整段 rit. 直接消失。现在按「间隔 ≤ 1 拍聚簇、≥3 点单调、跨度 ≥ 5%」折叠成一个 `rit. 120→60` 记号，时间轴仍用原始事件表精确换算；页眉 / HTML / MusicXML 三层同步，网页提示「其中 N 处渐快渐慢」
- [x] **长音跨小节（延音线）**：简谱的 `-` 是「延长一拍」，超过一小节的长音只能靠延音线分写。旧版把时值表上限当硬上限——`snapBeats` 里一句 `return 4.0` 把任何长于全音符的音截成 4 拍，余下的时间在小节里补成休止符：一个 6 拍长音写成 `| 3 - - - | 0 - 4 5 |`，唱到一半凭空静音两拍；MusicXML 同样变成「整音符 + 休止」。现在时值保住，跨小节自动分写（文本 / HTML 续写 `-`，MusicXML 写 `<tie start>` / `<tie stop>` 链，跨三小节就是 start → stop+start → stop）；同时修掉门限还原对长音的误放大（4 拍柱式和弦在复调轨上会变成 4.75 拍，小节线整体错位）
- [x] **同轨复调（一条轨两个声部）**：钢琴 MIDI 常把左右手写进同一个轨——右手旋律、左手长音铺底，同时发声、时值还各不相同。旧版只按「起始 tick 相同」判和弦，长音叠短音也被当成同一拍的和弦，而 `<chord/>` 的成员时值不等，4/4 的小节直接被撑成 8 拍（MuseScore 打不开）；文本谱同样把两个声部的音挤进一行。现在按「同拍同值 = 和弦、其余重叠音分声部」贪心拆开，MusicXML 用 `<backup>` 回退游标逐声部写、声部内各自成延音线，文本 / HTML 则把每个声部排成独立谱行（`[Piano · 声部1]` / `[Piano · 声部2]`）；单声部文件的输出与旧版逐字节一致
- [x] **SMPTE 时间基准**：MV / 视频配乐导出的 MIDI 常用 `division` 高字节为负的 SMPTE 记法（`0xE728` = 25 fps × 40 tick）。旧版把它当无符号 PPQ 读成 **59176**，一首 16 拍的曲子被压进 1 小节、还被拆成 3 个假声部。现在识别帧率与每帧 tick 数，按曲首速度折算成「每拍多少 tick」（本例 `500 tick/拍`），并把 SMPTE 下无意义的中途 `set_tempo` 归一掉（否则秒数与歌词会被二次缩放）；CLI / HTML 页眉 / 网页文件面板都写明「时间基准 SMPTE 25 fps × 40 tick → 500 tick/拍」
- [x] **format 2 独立序列**：format 2 的每条轨是**各自独立的曲子**（pattern），不是同一首的各声部。旧版把它们并到同一条时间轴：两段各 4 小节的音乐互相错位，同拍音被判成和弦。现在只转文件顺序里第一条含音符的轨，按轨 / 通道一并过滤轨名、歌词、力度、弯音、音色，页眉说明「共 N 段，只转换轨 K」；要别的段落用 `--track` 指定（从 0 起）
- [x] **事件流对齐与音符配对**：解析器过去对「文件写法不标准」太乐观，四个坑都是静默出错。`0xA0` 复音触后是 3 字节事件（状态 + 音高 + 压力），旧版落到兜底分支只跳 1 字节，遇到第一个就与事件流错位——一条 16 个音的轨最后报「未提取到音符」；同一个键还没抬手又按下（重复触键、转录软件常见）时旧版直接覆盖，前一个音凭空消失；轨结束时还按着没抬手的悬挂音被整条丢掉（少掉的音甚至把 C 大调带偏成 F / D 小调、还多判一个「弱起 3 拍」）；0x05 歌词分散在多轨时（两段词各一轨）按 tick 合并成一行，得到「春夜来风雨声花落」这种交错乱码。现在分别修成：按 2 字节跳过触后、重触发先收尾再起音、轨尾补收悬挂音、歌词只取音节最多的那条轨并说明忽略了另一条
- [x] **控制器语义**：`0xB0` 分支过去只认 CC11（表情）与 RPN，其余控制器一律「跳过两个字节」。但有五类控制器直接决定谱面：**CC64 延音踏板**（钢琴导出里琴键只按 1/4 拍，真正的音响由踏板决定，旧版写出 `1= 3= 5= 0 - - -`）、**CC120 / CC123 强制清音**（某些导出器拿它代替 note-off，旧版把悬挂音补成横跨全曲的幽灵长音，还拆出假声部）、**CC7 主音量**（与 CC11 同为渐强渐弱来源，只认 CC11 会整段丢掉力度记号）。现在收集五类事件、所有轨读完后统一后处理：踏板补时值到「抬起 / 同键重按」较早者并按通道隔离，清音截到正确 tick，CC7 并入力度表（同 tick 同通道让位给 CC11）；CLI / HTML 页眉 / 网页文件面板都写明改了什么；另支持 **CC66 持音踏板（Sostenuto）**：只保持踩下那一刻正按着的键，之后新弹的音不受影响，与 CC64「抬手时踩着就延长」的判定方向正好相反，两者共用一套迟滞配对、各算各的作用规则；另支持 **CC67 软踏板（Soft Pedal）**：踩下期间起音的音符力度按 ×0.7 衰减（110→77），只改 `velocity` 不改时值，也不动 CC11 / CC7 力度表，三种踏板共用同一套迟滞配对、各走各的作用规则
- [x] **HTML 谱面导出**：自包含网页，浏览器打开即可打印 PDF，含和弦标记、小节号、和弦竖向叠写；小节号/力度/速度独占标记行，和弦则挂在它管的那个音符正上方（标记行是从左往右排的，写在那里会被别的标记顶偏），三层互不侵入
- [x] **MusicXML 导出**：`--musicxml out.xml`，符合 3.1 规范（整数 `duration`、`<chord/>`、`<tie>` 跨小节延音、正确 `<fifths>`/`<clef>`/速度标记、和弦 `<harmony>` 含 `<root>`/`<kind>`/`<bass>`）；配合 `--lyrics` 还会写出 `<lyric>`（syllabic begin/middle/end）与一字多音的 `<slur>`，导进 MuseScore 有词可看、和弦符号也能显示
- [x] **歌词写入**：`--lyrics lyrics.lrc` 支持 LRC 格式，按时间戳精确对齐；一行词跨多小节、旋律音数多于字数（一字多音）时按行内音数铺开，不会全挤在第一小节，并在这些音上方画出连音线弧线
- [x] **LRC 按变速分段对齐**：`[mm:ss.xx]` 是真实秒，新的 `TempoTimeline` 按 `set_tempo` map 逐段反解成 tick，变速曲目的后半段歌词不再整体错位（120→60 BPM 时旧版能差出整整一小节）；同时支持 `[offset:±毫秒]` 整体平移与一行多个时间戳（副歌重复句），CLI / 网页版 / HTML / MusicXML 共用同一个解析器
- [x] 文本输出到文件：`--output out.txt`（含和弦标记）
- [x] 多轨选择：`--track 0`
- [x] **轨道列表诊断**：`--list-tracks` 列出每条轨的序号 / 名称 / 旋律音数 / GM 乐器名 / 歌词字数 / 是否鼓轨，选 `--track N` 前先看清该选哪条（纯诊断、不参与转换、不改变任何既有输出）
- [x] `--version` 打印版本号
- [x] **在线 Demo**：WASM 核心，浏览器内运行 C++ 代码
- [x] **减时线按拍连通**：一拍内的八分/十六分音符共用一条横线（十六分再叠平行线），而不是每个音各画一小段；和弦的减时线只画在最下面那个音上
- [x] **渐强渐弱按通道标注**：CC11/CC7 的 `cresc.` / `dim.` 只印在所属声部，伴奏通道的渐强不再串到旋律谱（旧版会同 tick 覆盖旋律的渐弱，谱面写 `[cresc.]` 而力度写 `[ff]→[pp]`）；`0x06` 段落名仍作全局标记，单通道文件三层输出逐字节零回归
- [x] **损坏 / 截断 MIDI 的安全解析**：`MTrk` 长度字段写着原值、文件却只下载到一半时，不再越过 buffer 末尾把堆里相邻内存当成新事件继续解析（那会凭空冒出幻影音符与乱码歌词）。所有事件统一按 `min(trkEnd, size)` 取硬边界，残缺事件整条丢弃，CLI / HTML / 网页文件面板写明「文件数据不完整」并按可用字节正常出谱；合法文件逐字节零回归
- [x] **CC67 软踏板**：踩下期间起音的音符力度按 ×0.7 衰减，重音记号 / 力度分析 / 网页播放 JSON 同步变化，时值与 CC11 力度表不动（没有 CC67 的文件逐字节零回归）
- [x] 654 项单元测试 + 64 组端到端冒烟测试 + 39 组 WASM 产物一致性检查（含产物版本号、源码一致性、「改了源码必须重编」与「重编了必须升版本」的双向纯 git 守护）

## 在线 Demo 功能

- 拖入 MIDI 文件即转简谱（文件不上传，全部在浏览器内解析）
- 25 种调性可选（自动识别 + 12 大调 + 12 小调）
- 歌词：文件自带 `0x05` 歌词时自动识别并提示「此文件自带 N 个歌词音节」；也可粘贴 LRC 文本或选择 `.lrc` 文件（优先级更高），并有「使用 MIDI 自带歌词」开关
- 曲中有变速时会提示「检测到 N 处变速，LRC 已按 tempo map 分段对齐」；`[offset:]` 与多时间戳同样生效
- 曲中有渐快 / 渐慢时会补一句「其中 N 处渐快渐慢，谱面按 rit./accel. 收成一个记号」——一段 rit. 在 MIDI 里是几十个 `set_tempo`，不点明的话会以为速度数据丢了
- 在线播放（Web Audio API 合成）
- 自动识别中途变拍号、中途转调、弱起、变速与鼓轨，无需任何开关；文件含转调时会提示「检测到 N 处转调，唱名已按段换算」
- 纯五声旋律会提示「检测到 G 徵调式，1=C 按宫音校正」，另有「五声调式宫音校正」复选框可切回大小调判定

- 下载 MusicXML（可用 MuseScore 继续编辑）
- 下载 PNG 谱面
- 复制简谱文本（一键复制到剪贴板）

### 记谱约定

数字为唱名（1=do），随调性移动；**小调按首调记作 `1=关系大调`，主音落在 `6` 上**（a 小调即 `1=C`，`6` 就是 A）；`'` 高八度、`,` 低八度（可叠加）；`#`/`b` 升降半音（书写跟调号走）；`0` 休止；`-` 延长一拍；`[C]` 和弦标记（只标旋律轨）；`[p]` 力度记号（按通道隔离）；`3(...)` 三连音。

时值后缀跟在数字后：`%%` 三十二分、`=` 十六分、`_.` 附点八分、`_` 八分、`.` 附点四分、无后缀为四分、`-` 为二分。完整对照表见 [BUILD.md](./BUILD.md#时值后缀)。

> **八度基准随 `1` 移动**：`1` 代表 do 所在八度，不是固定以 C4 为基准。所以 `--key G` 时 C5 写作 `4` 而非 `4'`。这是简谱的标准做法，早期版本以 C4 为基准导致所有音整体偏高一个八度点，已修正。

> **时值量化**（默认开启）：真实录音转出的 MIDI，note-off 普遍早于下一个音头（DAW 的门限时间，常见 85%），八分音符的时长只有 0.425 拍。直接拿这个时长查时值表会判成附点十六分，整份谱子的节奏全错。量化做法是：音头吸附到 1/24 拍网格（同时容纳 32 分音符与三连音），从全曲 `dur/ioi` 的众数估出门限因子还原音值，再吸附到最近的合法时值。`--no-quantize` 可关闭。

### 弱起小节怎么判

「弱起」是曲子从弱拍进唱、第一小节只占几拍（`| 5 | 1' 7 6 5 |` 里的那个 `5`）。MIDI 里它就从 `tick 0` 开始，第一小节天然不满，于是 `tick / 小节长` 划出来的网格整条左移一拍：谱面上每小节的重音落到第 4 拍，和弦也跟着错（弱起的 `5` 会被并进主和弦算成 `Cmaj7`）。

判定只用两条硬证据，宁可漏判也不误判——判错会让整份谱子的小节线全错，而漏判还能手动补救：

1. **曲子从 `tick 0` 直接起唱**。开头若干小节空白是前奏休止，不是弱起；
2. **全曲最后一个音收在小节线上**。弱起总长是 `P + N×小节长`，所以「末音位置 mod 小节长」就是弱起长度，就近吸附到整拍；并且弱起之后那一拍必须真有音起（否则只是长音停在小节中间，没有弱起）。

两条都成立时弱起长度只有一种解释。判不出来、或者乐谱本身收尾不规矩时，用 `--pickup N` 直接给拍数（可带小数，如 `1.5`），`--no-pickup` 回到旧行为。谱面头部会写「弱起 1 拍」——判错了能一眼看见。

> **跨小节切分**：小节线只由拍子位置决定，不由音符音头决定。所以整段前奏会老老实实写成 4 行 `0 - - -`，而不是把十几个 `-` 挤进第 1 小节；长音跨小节时也在小节线处断开，后段用 `-` 续写（6 拍长音 → `1 - - -` | `- -`）。

### 一字多音（melisma）怎么记

一行词往往只有几个字，旋律却唱了一串音（衬腔、拖腔、走句）。歌词按行内音数均匀铺开后，一个字会覆盖好几个音；简谱要在这些音上方画一条连音线，唱的人才能看出「这一个字拖过这几个音」，而不是每个音各唱一遍这个字。

三个输出层共用 `assignLyrics()` 给出的「字 → 覆盖区间」结果，不再各写一套分配逻辑：

| 输出 | 一字多音的表现 |
| --- | --- |
| HTML / 网页版 | 同组且连续的音符列包进一个 `.sgrp`，用 CSS 画一条跨全组的弧线；遇到小节线、休止符就断开，各段独立成弧 |
| MusicXML | 首音 `<syllabic>begin</syllabic>` + `<slur type="start"/>`，中间音 `middle`（带 `<extend/>`），末音 `end` + `<slur type="stop"/>`；一音一字则写 `single` |
| 文本简谱 | 只输出歌词字，不画弧线（纯文本没有排版能力） |

弧线不能和和弦字母、高八度点挤在一起：有连音线时把音符行的上留白从 18px 抬到 36px，自下而上依次是「数字 → 连音线 → 和弦字母」，三者互不侵入。只抬高存在连音线的那一轨，其余谱面行距不变。

> **没有歌词时行为不变**：既没给 `--lyrics`、MIDI 里也没有 `0x05` 歌词事件时，`--musicxml` 不会写出任何 `<lyric>` / `<slur>`，网页版同理。

### MIDI 内置歌词怎么读

很多卡拉 OK / 人声 `.mid` 用 `0x05 lyric meta` 自带歌词：每个事件带精确 tick，通常一个事件就是一个音节。这跟 LRC 完全是两种数据——LRC 只有「一行词从哪一刻开始」，字要靠行内音数均分；内置歌词的 tick 是文件作者标好的，塞进 `assignLyrics()` 反而会把精确位置抹平，还会把相邻音节粘成一个词。所以两条通路各自规整，最后都汇成同一个 `LyricAssignment`，输出层不区分来源。

事件流比「一个事件一个汉字」脏得多，规整规则（事实标准，测试素材 `karaoke.mid` 全部覆盖）：

| 写法 | 处理 |
| --- | --- |
| `-`、`_`、空串、纯空白 | 一字多音的延续，不产生新音节 —— 前一个字的区间自然延长，正好对应简谱的连音线 |
| `/`、`\`、CR/LF | 换行或分隔，跳过 |
| `@KMIDI` / `@TITLE` 等 `@` 开头 | 文件元数据，跳过 |
| `+` 前缀 | 续行标记，去掉后保留内容 |
| 中文标点 | 不占音节；汉字一字一音节 |
| `Hello ` 这类英文 | 连续 ASCII 字母算**一个**音节（不是五个），尾随空格 trim |

优先级是「显式 `--lyrics` > MIDI 内置 > 无词」，谱面页眉会写「歌词：MIDI 内置（5 音节）」或「歌词：外部 LRC」，来源错了能一眼看见。另外，`0x05` 事件所在的轨就是文件作者标出的人声轨，这比按音符数、单音率猜都可靠——旋律轨判定会给它额外加分（format 0 只有一条轨、或歌词分散在多轨时不采信，避免误判）。

> 关掉内置歌词是「清空事件表」而不是加一个渲染开关：歌词事件同时还是旋律轨判定的证据，关掉就得连证据一起消失，否则会出现「谱面无词、旋律轨却被自带歌词带偏」这种半开半关的状态。

### 中途变拍号怎么划小节

旧实现每次读到一个 `0x58` 拍号事件就覆盖 `data.timeSig`，于是「前 4/4、后 3/4、再 6/8」的曲子整份谱子都按最后一个 `6/8` 划小节线。更糟的是弱起判定依赖「末音 tick mod 小节长」，小节长一错就会凭空算出「弱起 4 拍」，把网格再整体平移一次——两个错误叠在一起，谱面完全没法看。

现在拍号和速度一样是一张按 tick 排序的 map。`normalizeMeterMap()` 先去掉多轨重复声明（conductor 轨和乐器轨常各自写一遍同样的 `0x58`），`meterChangesOf()` 只留实质变化；`barGridOf()` 据此铺出一张**逐小节的边界表**（每小节起点 tick + 该小节生效的拍号），文本 / HTML / MusicXML 三个输出层共用：

| 场景 | 处理 |
| --- | --- |
| 拍号事件正好落在小节线上 | 从那一线起换新小节长度，前后小节号连续 |
| 拍号事件落在小节中间 | 在那里截断当前小节，新拍号从事件 tick 起生效（导出器写歪时的降级） |
| 多轨重复声明同一拍号 | 归一化时去重，不算变拍号 |
| 中途变拍号 + 弱起 | 自动弱起判定直接停用（`mod` 公式不再成立），需要时用 `--pickup N` 手动指定 |

和声窗长度也按当前小节的拍号取，不会用 4/4 的半小节窗去切 3/4 段。MusicXML 在变化小节重写一次只含 `<time>` 的 `<attributes>`，否则 MuseScore 会把后半首也按曲首拍号解释。

> **为什么用边界表而不是继续做除法**：只要有第二个拍号，`tick / barLen` 就不再是常数除法，弱起、变速、歌词、和弦所有依赖网格的地方都要知道「这一小节到底多长」。铺一张表比在各处散落分段判分支可靠得多，而且单拍号文件的表与旧除法完全等价（回归测试锁住）。

### 中途转调怎么记

简谱是**首调**记谱：调一变，同一段旋律的唱名就得整体重算。旧实现每读到一个 `0x59` 调号事件就覆盖 `data.keySig`，于是「前 1=C、副歌转 1=D、尾段转 1=F」的曲子整份谱子都按最后一个 F 大调换算——同一个 C4 在前半首本该写 `1`，却全写成 `5,`。和拍号一样，调号现在是一张按 tick 排序的 map。

关键观察：**首调的 `1` 只由调号的升降数决定，与大小调无关**——a 小调和 C 大调都是 `1=C`。五度循环里每多一个升号，`do` 上移 7 个半音，所以转调幅度是一个**相对量**，而不是 MIDI 里写的绝对调号：

| 场景 | 处理 |
| --- | --- |
| 曲首 `sf=0`、副歌 `sf=+2` | 曲首 `1=C`，副歌起整体移 +2 半音 → `1=D` |
| 用户 `--key G` 指定曲首 | 整条链平移：`1=G → 1=A → 1=C`，不会跳回 MIDI 的绝对调号 |
| 用户 `--key Em`（小调） | 按首调记作 `1=G (E小调, 主音=6)`，后续各段同样平移，主音仍落在 `6` |
| 转回原调（C→D→C） | 相对曲首没变，但谱面必须再写一次 `1=C` |
| 转调点落在小节中间 | 吸附到该小节起点，不允许一小节里前半用旧唱名、后半用新唱名 |
| 多轨重复声明同一调号 | 归一化时同 tick 去重，不算转调 |

三个输出层共用 `KeyMap`，按音符所在 tick 取当前调性：

| 输出 | 表现 |
| --- | --- |
| 文本简谱 | 页眉 `1=C 大调 → 1=D(第5小节) → 1=F(第9小节)`，变化小节写 `[转1=D]` |
| HTML / 网页版 | 页眉同上，变化小节的标记行加紫红色 `转 1=D` 标签，与拍号 / 速度标记互不遮挡 |
| MusicXML | 变化小节重写 `<key><fifths>/<mode>`；`<key>` 按规范排在 `<time>` 之前，两者同时变化时合进一个 `<attributes>` |

降号调里和弦根名也跟着走：F 大调段的 Bb 和弦写 `Bb`，不是 `A#`。

> **两个取舍**：一是大小调之间的切换（`0x59` 第二字节变化而升降数不变）不单独标注，因为首调的 `1` 和唱名都没变，简谱歌本也不另行换调号；二是等音按最简写法归一（7 个升号的 `C#` 记作 `1=Db`）。文件里完全没有 `0x59` 事件时无从检测转调，此时用 `--key` 指定曲首、或按单一调性记谱即可。`--no-key-changes` 可一键关掉整条调号 map（事件表仍保留，曲首调号还要用来判调性）。


## 时间轴与 LRC 歌词

MIDI 里同时存在两套坐标：谱面用 **tick**（每四分音符 `division` 个），LRC 用 **真实秒**。变速时两者不再是固定比例——`♩=120 → 60` 之后一拍从 0.5 秒变成 1 秒。旧解析器把整首歌当成曲首速度，用 `秒 / (60/bpm) × division` 一把换算：

| LRC 时间戳（`tempolrc.mid`，第 5 小节起 60 BPM） | 固定 120 BPM | tempo map | 实际位置 |
| --- | --- | --- | --- |
| `[00:12.00]` | tick 11520 | **tick 9600** | 第 6 小节起点 |
| `[00:16.00]` | tick 15360（曲终，词丢失） | **tick 11520** | 第 7 小节起点 |
| `[00:20.00]` | tick 19200（曲终外，词丢失） | **tick 13440** | 第 8 小节起点 |

也就是说，副歌一变速，后半首的歌词会整段挂到错误的小节，甚至直接消失。这类问题在看谱时很容易被误当成「LRC 文件本来就不准」。

`TempoTimeline` 把 `0x51 set_tempo` 序列编译成分段表（tick / 该点真实秒 / 本段每四分音符微秒数），提供 `tickToSeconds()` 与 `secondsToTick()`。音符秒数（`recomputeSeconds`）与 LRC 歌词现在共用这一张表，不会再出现「音符对、歌词错」。构造时统一排序、同 tick 后写覆盖、丢弃非法 BPM，越过末段时间按末段速度线性外推。

| LRC 写法 | 处理 |
| --- | --- |
| `[mm:ss.xx]歌词` | 秒叠上 offset 后由 tempo map 反解成 tick |
| `[offset:-2000]` | 所有时间戳整体平移（正值=歌词延后），大小写不敏感；多个取最后一个 |
| `[00:00.00][00:08.00]副歌` | 展开成两行，按 tick 稳定排序（副歌重复句不用抄两遍） |
| `[ti:]` / `[ar:]` / `[al:]` | 元数据行跳过 |

新增 `parseLrcText(text, data)` / `parseLrcLines(path, data)` / `parseLrc(path, data)` 三个重载；旧的 `(division, bpm)` 签名保留，内部按曲首单速构造一条等价时间轴，现有调用方零改动。WASM 版关闭了 C++ 异常，数字解析仍走手写的不抛异常版本，畸形 LRC 不会让页面崩掉。
## 五声音阶与民族调式

Krumhansl-Schmuckler 用七声大/小调轮廓打分。纯五声旋律 `C D E G A`、终止音落在 G 时，相关度最高的是 **G 大调**，于是谱子写成 `1=G`；而中国民歌里这是 **G 徵调式**，宫音是 C，简谱应该写 `1=C`（G 记作 `5`）。终止音不是宫音在民歌 / 古风曲里是常态，硬套大小调主音会让整份谱子的唱名全错。

`detectPentatonic()` 只看旋律轨（不是全部轨，伴奏的柱式和弦会把偏音灌进来）：

| 步骤 | 做法 |
| --- | --- |
| 音级直方图 | 按时长加权统计 12 个音级；取最后一个音作终止音 |
| 初筛 | 音级 < 4 或 ≥ 7 直接放弃（太少定不了调式；七声交回 KS） |
| 枚举宫音 | 12 个候选宫系统各取 `宫商角徵羽 = 0/2/4/7/9`；终止音必须是该系统正音 |
| 偏音容忍 | 六声只允许一个偏音（`清角 4 / 变徵 #4 / 闰 b7 / 变宫 7`），且时长占比 ≤ 8%；两个偏音视为七声 |
| 歧义拒绝 | 只有四五个音级时可能两个宫系统都完美覆盖（如 `C D G A` 既是 C 宫也是 F 宫），最优与次优覆盖率差 < 0.4% 就宁可不报 |
| 调式名 | 终止音相对宫音的音程决定 宫/商/角/徵/羽 |

校正只在**文件没有 `0x59` 调号**、且检测通过时才发生；谱面唱名仍只由 `tonicPitchClass + isMajor` 决定，`scaleLabel` 只是文字标注，所以 `KeyMap` 转调、等音写法、MusicXML `<key>` 这些既有链路一行都不用改。宫音与 KS 本来一致时（例如 a 小调式的羽调旋律）只补一条调式名，唱名一个字不动。

| 场景 | 处理 |
| --- | --- |
| C 宫、终止 G（G 徵调式） | `1=C 大调 · G 徵调式（宫音 C）`，G 记作 `5` |
| 用户 `--gong C` | 强制 `1=C`，按当前终止音反推调式名 |
| 用户 `--no-pentatonic` | 完全回到 KS（上例变回 `1=G`） |
| 文件带 `0x59` 调号 / 七声 / 偏音过多 | 以 MIDI 调号或 KS 为准，不做校正 |
| 网页版 | 复选框「五声调式宫音校正」，提示「检测到 G 徵调式，1=C 按宫音校正」 |

## 力度与演奏法

解析层其实一直在读这些数据——CC11 Expression、note-on velocity、pitch bend、`0x06` marker——但除了 CC11 被文本谱和 HTML 各写了一遍粗糙的力度分级外，其余全部丢掉了，MusicXML 更是一点力度都没有。`ExpressionMap` 把判定收成唯一权威：构造一次，三个输出层只读结果，于是「网页上有 mf、导进 MuseScore 却什么都没有」这类半开半关的状态不复存在。

| 数据源 | 判定 | 文本谱 | HTML | MusicXML |
| --- | --- | --- | --- | --- |
| CC11 (`0x0B`) | 六档力度 `pp`~`ff`，按通道隔离；跨档才标 | `[mf]` | `dyn` 标记 | `<direction><dynamics><mf/></dynamics><sound dynamics="75"/>` |
| CC11 单调段 | 连续 ≥3 点、同向、跨度 ≥24 → 渐强 / 渐弱，起止成对 | `[cresc.]` / `[dim.]` | `cresc.` / `dim.` | `<wedge type="crescendo"/>` + `type="stop"` |
| `0x06` marker | 段落名 | `[副歌]` | `section` 标记 | `<direction><words>副歌</words>` |
| note-on velocity | 显著高于邻音（≥24）→ 重音 `>` | `5>` | 音符右上角 | `<articulations><accent/></articulations>` |
| 弯音形状 | 单调 ≥3 点 → 上滑 `↗` / 下滑 `↘`；往复振荡 → 颤音 `tr` | `5↗` / `5tr` | 音符右上角 | `<slide>` 成对 / `<trill-mark/>` |
| 音头门限 | 等间隔流里显著短于常态 → 断奏 `▼` / `·` | `5▼` | 音符右上角 | `<staccatissimo/>` / `<staccato/>` |

**断奏为什么要加「等间隔」闸门。** MIDI 没有显式 staccato 事件，短 note-off 既可能是断奏，也可能只是「八分音符 + 休止」。绝对阈值会把真实人声 MIDI 里每小节末的短音全标成断奏（开发中实测误标 33 处）；改用「相对全轨门限中位数」能排掉大部分，但仍分不清 `0.25 拍音符 + 1.75 拍休止`。所以只在**音头间隔几乎一致**（≥90% 相同，即谱面上没有休止）时才判：此时短 gate 只剩断奏一种解释。节奏混合的旋律整轨拒绝判定——宁可漏判，也不给整份谱子撒上假的 `▼`。

演奏法按 `(tick, channel)` 索引而不是只按 tick：旋律与伴奏常有同一 tick 的音头，按 tick 存会让伴奏「继承」旋律的滑音记号（压力素材里踩到过并修掉了）。段落名（`0x06` marker）属于整份谱，只印在第一条声部／旋律轨；**力度档位与渐强渐弱都按通道各自写**。`ExpressionMark` 带通道，同一 tick 不同通道的渐变分列，输出层把当前声部通道传进 `inRange()`——否则伴奏的 `[cresc.]` 会盖掉旋律的 `[dim.]`，谱面和同一行的 `[ff]→[pp]` 自相矛盾。播放用的音符 JSON 也补上了真实的 `velocity`，网页据此区分强弱。

`--no-dynamics`（网页上是「力度与演奏法」复选框）让整张表情图为空，但事件表本身保留，调性与旋律轨判定不受影响。**没有任何表情数据的文件输出不变**：真实人声曲目《蝶衣碎雪》带 LRC 回归的 MusicXML 逐字节一致，HTML 谱面内容也逐字节一致（仅内联 CSS 多了几条定义）。

## 和弦怎么标

和弦由伴奏轨按和声窗统计音级后匹配模板（旋律轨自带经过音，不参与）。三和弦与七和弦的差别是「特征音在不在场」，转位则完全由低音决定——`C E G` 和 `E G C` 的音级集合一模一样，谱面却必须一个是 `C`、一个是 `C/E`。

| 现象 | 处理 |
| --- | --- |
| 低音是和弦音但不是根音 | 写斜杠 `C/E` / `G/B`，MusicXML 写 `<bass>` |
| 低音是和弦外音（经过音 / 持续音） | 不写斜杠。低音只是路过，硬凑成 `C/F` 反而是错的 |
| 多出 b5 或「挂四 + 小七」 | `Bm7b5` / `G7sus4`；只有特征音真在场才升格，否则仍是三和弦 |
| 低音在独立的贝斯轨上 | 照常参与判定——低音常常根本不在钢琴轨里 |

MusicXML 的 `<kind>` 用标准值（`major` / `half-diminished` / `suspended-fourth`…），显示后缀走 `text` 属性，于是 MuseScore 既能正确识别语义，又能原样显示 `m7b5` / `7sus4` 这种简写。

## 渐快渐慢怎么记

DAW 里的渐慢不是「一条命令」，而是**画出来的一条速度曲线**——导出到 MIDI 就是几十个连续的 `set_tempo`（自动化节点通常每 1/16 ~ 1 拍一个）。这些点对时间轴换算是必需的：没有它们，音符秒数和 LRC 歌词全都会错。但它们**不是谱面记号**。

旧版把每个点都当一次变速，于是同一段 rit. 在三个输出层各坏一种：

| 输出 | 旧行为 | 问题 |
| --- | --- | --- |
| 页眉 | 取前 5 个点列成 `♩=120 → 120(第3小节) → 116(第3小节) → 113(第3小节) → …` | 五条全指同一小节，读者拿不到任何信息 |
| HTML | 每个小节起点采样一次速度 | 渐慢段每小节都冒一个 `♩=116` / `♩=112`，满屏都是没有意义的数字 |
| MusicXML | 只在「节点 tick 正好等于小节线」时写 `<metronome>` | 自动化节点几乎不可能落在小节线上，整段 rit. **彻底消失** |

乐谱的写法只有一个记号：`rit.` / `accel.`。`tempoMarksOf()` 把事件序列收敛成谱面该有的那几个：

| 判据 | 取值 | 理由 |
| --- | --- | --- |
| 聚簇间隔 | ≤ 1 拍（`division` tick） | DAW 的节点再密也不密过 1/16 拍；而两次**独立**的阶跃变速不可能挤在一拍内 |
| 当成渐变 | 簇内 ≥ 3 点、单调（允许持平）、总跨度 ≥ 5% | 两点是阶跃的手滑，来回拉是自动化抖动，120→118 写 rit. 是误导 |
| 其余 | 退化成 `♩=N`，取簇末速度 | 宁可少一个 rit.，也不给谱面撒假的 |
| 曲首速度 | 恒为独立阶跃记号 | 不管后面接什么，读者都得先知道「从多快开始」 |

时间轴（`TempoTimeline`）仍用**原始**事件表逐点精确换算，折叠只发生在输出层——这是本项目一贯的分层：事件表是播放的真相，输出层只挑该显示的。

| 输出 | 表现 |
| --- | --- |
| 文本页眉 | `♩=100 → accel. 100→140(第2小节) → rit. 140→80(第4小节) → 120(第8小节)` |
| HTML | 阶跃 `♩=120`（蓝框）、渐变 `rit. 140→80`（棕框），渐变只标起点，不逐小节采样 |
| MusicXML | 渐变写 `<words>rit.</words>`，并在它**落定**的那一小节补一个 `<metronome>` 写终点速度 —— 谱面是标准记法，MuseScore 的播放也能跳到正确 BPM |

## 长音怎么记

简谱的 `-` 是**延长一拍**，不是一个可以随便伸缩的符号。一个音超过一小节，就只能在
小节线处切开、用延音线续写：

```
| 3 - - - | - - 4 5 |        ← 6 拍长音：bar3 四拍 + bar4 两拍
| 1' - - - | - - - - | - - 7 6 |   ← 10 拍长音：跨三小节
```

这是简谱与五线谱都要遵守的规则：小节线属于**拍子**，不属于音符。

旧版在量化阶段就把长音截死了：`snapBeats()` 的时值表最大到全音符（4 拍），
超出时直接 `return 4.0`。于是 6 拍的长音变成 1920 tick，剩下的 960 tick 成了空洞，
三个输出层只好在下一小节补休止符——谱面写的是「唱四拍，然后静音两拍」。

| 环节 | 现在的做法 | 为什么 |
| --- | --- | --- |
| `snapBeats` | 超过全音符时吸附到 1/4 拍，**不截断** | 长音的真实时值必须保住；「一个音符符号写不下」不等于「只唱四拍」 |
| 门限还原 | 只作用于 3 拍以下的音符 | 门限因子描述的是断奏音提前收尾；长音是按住不放的，`旧时值 / 0.86` 会把 4 拍虚增成 4.65 拍 |
| 跨小节切分 | 首段照常写数字，后续段写 `-`，末段带时值后缀 | 简谱的延音线就是这个写法 |
| MusicXML | 每段一个 `<note>`，`<tie type="start">` / `<tie type="stop">` 首尾相接 | 跨三小节时中间段同时带 stop 与 start，MuseScore 才画得出连续弧线 |

复调轨（柱式和弦）是这套规则里最容易翻车的地方：单声部轨还有「响到下一个音头」
兜底，复调轨没有，门限虚增会**真的**落进谱面——每小节溢出 3/4 拍，之后所有小节线
整体错位。`long_tie.mid` 里专门放了一条每小节一个 4 拍三和弦的钢琴轨来锁这个行为。

## 复调怎么排

一条 MIDI 轨不等于一个声部。钢琴 MIDI 最典型的形态就是**左右手写进同一个轨**：
右手四分音符走旋律，左手全音符铺低音，两边同时发声、时值还各不相同。

判断「是不是和弦」不能只看起始 tick。真正该写成一个和弦（`<chord/>`）的，是
**同拍且同值**的一组音——它们本就该占同一格。同拍但时值不同的两个音不是和弦，
是**两个声部**：

| 情形 | 判定 | 输出 |
| --- | --- | --- |
| 同拍 + 同值 | 真和弦 | 同一格，MusicXML 写 `<chord/>` |
| 同拍 + 不同值 | 两个声部 | 拆开，各占一条声部线 |
| 上一个音还没收尾，下一句就进来 | 两个声部 | 拆开 |
| 超过 3 个声部 | 并进最早结束的那个 | 对齐成同值和弦，必要时截短 |

旧版只判「起始 tick 相同」，于是 `C3`（全音符）和 `C5`（四分音符）被当成同一拍的
和弦写出去。`<chord/>` 的成员时值不等，MuseScore 按第一个音的时值算这一格，
后面的音继续往后排——**4/4 的一小节被撑成 8 拍**，导出的文件打不开：

```
应写（两个声部各 4 拍）        旧版（一格塞进 8 拍）
voice 1: C5 D5 E5 F5          <note> C3 whole </note>
<backup 1920/>                <note><chord/> C5 quarter </note>
voice 2: C3 (whole)           <note> D5 quarter </note> …   ← 3360 ≠ 1920
```

三个输出层各有各的排法：

| 输出 | 复调怎么排 |
| --- | --- |
| 文本谱 | 每个声部一块，标题写 `[Piano · 声部1]` / `[Piano · 声部2]`，各自按小节换行 |
| HTML | 每个声部一块谱面（`.staff`），标题右侧挂 `声部 N` 小标签 |
| MusicXML | 同一个 `<part>` 内先写声部 1，`<backup>` 退满一小节，再写声部 2；`<voice>` 递增 |

`<backup>` 的长度必须是**这一小节的实际长度**而不是固定 4 拍：弱起小节和变拍号
小节都短于 4 拍，写死会让第二个声部整体错位。换声部之前也要先把上一个声部
补到小节末尾，否则 `<backup>` 一回退，它的尾巴就丢了。

声部数上限取 3。真实钢琴谱很少超过三声部，而无上限的贪心会在密集段落里炸成
十几条声部（每个同拍音都新开一条）。超过上限时把余下的音并进最早结束的声部，
并把同拍的音对齐成同一时值——宁可退化成和弦，也不能让小节时值溢出。

`polyphony.mid` 是这条链路的回归素材：右手四分音符 + 左手全音符，其中一个低音
跨小节，同时锁住 `<backup>`、声部内 `<tie>` 和「小节正好 4 拍」三件事。

## 文件头里的时间基准

`MThd` 头只有四个字段，其中两个一直被整块跳过，于是两类文件悄悄转错。

**division 高字节为负 = SMPTE。** 这是视频配乐 / MV 工程的记法：高字节是「负帧率」
的补码，低字节是每帧 tick 数。`0xE7 0x28` = 25 fps × 40 tick，也就是每秒 1000 tick。
高字节的符号位一旦被当无符号读，`0xE728` 就成了 **59176**——一首 16 拍的曲子
被塞进 1 小节（59176 tick 才是一拍），量化网格随之错乱，还会因为「同拍不同值」
被误判成复调拆出 3 个假声部：

```
应得（500 tick/拍，4 小节）        旧版（59176 tick/拍）
| 1 2 3 4 | 5 6 7 1' |             [Smpte Vocal · 声部1] 1%% 2%% 3%% 1%% 2%% 3%% |
| 1' 7 6 5 | 4 3 2 1 |             [Smpte Vocal · 声部2] 4%% 5%% 6%% 7%% 1'%% |
                                   [Smpte Vocal · 声部3] 4%% 5%% 6%% 7%% 1'%% |
```

SMPTE 里的 tick 是**绝对时间**（`tick ÷ (fps × ticksPerFrame) = 秒`），但简谱的一切
都按「拍」算，所以必须挑一个速度把时间换成拍：取曲首 `set_tempo`（没有就 120 BPM），
折算出的 `division` 就是「每拍多少 tick」，下游的 `tick / division` 照样是拍数，
三个输出层一行都不用改。随之要做的归一：SMPTE 下中途的 `set_tempo` **并不改变
绝对时间**，若留给 `TempoTimeline` 会把秒数二次缩放（音符与 LRC 歌词一起错位），
所以只保留曲首那一个点。

**format 2 的每一条轨是独立的曲子。** format 0/1 的多轨是同首曲子的各声部，
format 2 则是「一个文件装了多个 pattern」——每条轨各自从 tick 0 起算。合并到同一条
时间轴上，两段音乐的小节线互相错位，同时发声的音还会被判成和弦。现在只取文件
顺序里第一条含音符的轨，其余轨的音符、轨名、歌词，以及只属于它们的通道的力度 /
弯音 / 音色全部一并过滤，页眉写「共 2 段，只转换轨 0」；`--track 1` 可以换一段，
此时解析层不提前裁剪（`loadMidiFile(..., keepAllFormat2 = true)`）。

| 输出 | 文件头提示 |
| --- | --- |
| CLI | 转换前打印 `时间基准 SMPTE 25 fps × 40 tick → 500 tick/拍（按 ♩=120 折算）` |
| HTML | 页眉元信息行追加同一句；format 2 再追加「共 N 段，只转换轨 K」 |
| 网页版 | 文件面板提示区用 `_midi2jianpu_file_header_info` 取同一段文字 |

两个素材分别锁住这两条：`smpte.mid`（0xE728 + 第 9 拍插一个 400BPM 的
`set_tempo`，用来验证归一）与 `format2.mid`（SongA 4 小节 / SongB 2 小节）。

## 事件流对齐与音符配对

文件头读对了，事件流本身也可能读歪。下面四种写法在真实文件里都不罕见，而它们
**不会报错**，只会让谱面悄悄少东西。

**0xA0 是 3 字节事件。** 复音触后写作「`0xA0` + 音高 + 压力」。旧版把它当未知
事件，按 1 字节跳过，于是每遇到一个触后就少读一个字节：后面的 delta 时间被当成
数据、数据被当成 delta，整条轨从那里开始错位。16 个音的轨最后连一个音都提不出来，
CLI 只报一句「未提取到音符」——看起来像文件坏了，其实是解析器数错了字节。同样按
「1 字节」处理的还有 `0xD0`（通道触后，本来就 1 字节）与 `0xF1`/`0xF3`；`0xF2`
（song position pointer）是 2 字节，`0xF6` 起的系统实时消息则是 0 字节，现在都分开写。

**同一个键没抬手又按下，是两个音。** 重复触键、踏板踩法、转录软件都可能让
`note-on` 出现在前一个音的 `note-off` 之前（同音高、同通道、同轨）。旧版用
`active[key] = ...` 覆盖表项，前一个音就此消失——8 个音只剩 7 个。现在先把前一个
音收到重触发点（力度保留各自的），再以新力度起音；同一 tick 重复按下则直接换掉，
不会凭空补出一个十六分音符。

**轨尾悬挂音要补收。** 有些导出器不给最后一个音写 `note-off`，轨就结束了。旧版
把它整条丢掉：`dangling.mid` 里 16 个音的 C 大调音阶只剩 15 个，缺的那个音还把
调性猜测带偏成 **F / D 小调**，并多判出一个「弱起 3 拍」。现在按本轨最后一个事件
补收（时长至少一个十六分音符），调性与弱起都回到正常。

**0x05 歌词可能分散在多轨。** 卡拉 OK 文件常把第一段词、第二段词各放一轨，也有
伴奏轨拿 `0x05` 存和弦名。旧版按 tick 把所有轨合并成一行：

```
旧  春夜来风雨声花落…        ← 两段词交错，音节数 20
新  春眠不觉晓处处闻           ← 只取音节最多的那条轨，音节数 10
```

现在先按轨统计有效音节，只取最多的那条（并列时取轨号小的），页眉与命令行都写明
「另 1 轨的 10 个音节已忽略」。顺带的好处：`midiLyricTrack()` 不再因为「歌词跨
多轨」就一律放弃，人声轨证据在双段词文件里也能用上。

| 素材 | 旧版 | 现在 |
| --- | --- | --- |
| `aftertouch.mid` | 未提取到音符 | 16 个音符 / 4 小节 |
| `retrigger.mid` | 7 个音符 | 8 个音符（两个 C4 都在） |
| `dangling.mid` | 15 个音符、1=F D 小调、弱起 3 拍 | 16 个音符、1=C、无弱起 |
| `twolyrics.mid` | 20 个音节、两段词交错 | 10 个音节、只取第一段 |

## 控制器不是可以跳过的字节

事件流对齐之后，`0xB0`（控制器）分支还有一层假设：除了 CC11 表情和 RPN，
其余控制器都只是「读过两个字节然后丢掉」。但其中五类直接决定谱面长什么样，
而且旧版全都不会报错。

**CC64 延音踏板：抬手不等于消音。** 钢琴 MIDI 里非常常见的写法是 DAW 把
note-off 紧贴 note-on 导出（每个键只按 1/4 拍），真正的音响长度靠踏板控制。
只看按键时长就会得到一串十六分音符加长休止：

```
旧  1= 3= 5= 0 - - -  |  1= 3= 5=  |
新  1 - - - 3 - - - 5 - - -  |  （每小节一个 4 拍的持续和弦）
```

规则定得很死，没有主观门限：一个音若在踏板踩着时抬手，就延长到
**「踏板抬起」与「同一个键下一次按下」里较早的那个**（同键重击会终止前一次
音响），并按通道隔离——踏板是通道级控制器，通道 0 踩下不能给通道 1 补时值。
踏板事件写在 conductor 轨上也照常生效，所以修正在**所有轨解析完之后**统一做：
逐轨即时处理会按「文件顺序」而非「时间顺序」读事件，先处理轨 0 的未来事件、
再处理轨 1 的过去事件。`rawDurationTicks` 故意不改，它是量化前的按键时长，
断奏 / 倚音判据靠它——踏板带来的共鸣不是按键时长，写回去会把整首判成连奏。

**CC66 持音踏板：只保持踩下那一刻正按着的键。** 真钢琴的中踏板（Sostenuto）
与右踏板语义相反：CC64 看「抬手时踏板是否踩着」，会把踩下之后新弹的音也留住；
CC66 看「踩下时这个键是否已经按着」，之后新弹的键照常在 note-off 结束。所以
两种踏板**不能合并成一条时间轴**。`buildPedalRanges()` 让它们共用同一套迟滞
配对（踩下 `>= 64`、抬起 `<= 32`、中间值保持前态），但作用到音符时各走各的
判据，最后取更晚的终点；同键重击与强制清音对两者一视同仁。`sostenuto.mid`
里 C4 / E4 / G4 在 tick 0 按下、tick 240 踩下 CC66、tick 480 抬手、tick 1920
抬起，同 tick 480 新弹一个 D4：三个和弦音写全音符（1920 tick），D4 仍是四分
音符（480 tick）。旧实现把 CC66 当普通两字节跳过，和弦只剩一拍。

**CC67 软踏板：击弦变轻，按键时长不变。** 真钢琴的左踏板（una corda）减弱的是
击弦力度与音色，不是延音。所以它与 CC64 / CC66 共用同一套 `buildPedalRanges()`
迟滞配对，作用到音符时却只改 `velocity`：`(v * 7 + 5) / 10`（×0.7 四舍五入，
下限夹到 1），`durationTicks` / `rawDurationTicks` 一个字节都不动。CC11 / CC7
构成的力度表属于另一条控制链，也不能改写，否则会凭空多出一档力度。
`soft_pedal.mid` 在 `[1200, 2000)` 踩下 CC67，8 个音里两处 110 的强音本该
各印一个 `>`；踏板内那一处降到 77 后重音消失，谱面只剩 1 个 `>`，
而 8 个音的时值与没有 CC67 的对照文件逐字节相同。

**CC120 / CC123 强制清音。** 有些导出器不写 note-off，改用 All Notes Off 收尾。
旧版不认这个控制器，于是那个音被「轨尾悬挂音补收」逻辑一路补到曲末，
横跨整首曲子，还会因为与其他声部重叠被 `splitVoices` 拆成假声部：

```
旧  [Piano · 声部1] 1 - - -  | - - - -  |        ← 幽灵长音
    [Piano · 声部2] 0 - 2 3  | 4 5 6 7  |
新  [Piano] 1 0 2 3  | 4 5 6 7  |             ← 一条声部，首音正好 1 拍
```

**CC7 主音量也是强弱来源。** GM 里 CC7 是通道主音量、CC11 是表情，两者都能
承载渐强渐弱。只认 CC11 时，一个写了 8 个 CC7 点（20 → 118）的文件转出来
连一个力度记号都没有。现在 CC7 并入 `dynamics`；同一 `(tick, 通道)` 若 CC11
也在则让位给表情，避免凭空多出一档。

| 输出 | 说明 |
| --- | --- |
| CLI | 转换前打印 `延音踏板：补长 6 个音（2 个踏板事件）` / `持音踏板：保持 3 个音（2 个事件）` / `软踏板：衰减 2 个音的力度（2 个事件）` / `强制清音：截尾 1 个音` / `CC7 主音量：补入 8 个力度点` |
| HTML | 页眉元信息行追加同一段文字 |
| 网页版 | 文件面板用新导出 `_midi2jianpu_controller_info` 取同一段文字 |

六个素材分别锁住这五条：`pedal.mid`（踩到全曲第 8 拍，第 4 拍同键重按，
用来验证「重按截断」）、`allnotesoff.mid`、`cc7volume.mid`、
`pedal_channels.mid`（通道 0 踩 / 通道 1 不踩，并含一个「抬踏板之后才松键」
的音）、`sostenuto.mid`（CC66 只保持踩下瞬间正按着的三个和弦音）、`soft_pedal.mid`（CC67 只衰减踩下期间起音的力度，重音从 2 个减到 1 个，时值不变）。最后一份
踏板通道隔离素材刻意稀疏，冒烟测试用 `--no-pickup` 固定网格，
只检查四个音各自的时值 `1920 / 120 / 120 / 120`。

| 素材 | 旧版 | 现在 |
| --- | --- | --- |
| `pedal.mid` | 6 个十六分音符 + 长休止 | 6 个 4 拍音，每小节一个持续和弦 |
| `allnotesoff.mid` | 幽灵长音 + 2 个假声部 | 7 个音 / 1 条声部，首音 1 拍 |
| `cc7volume.mid` | 无力度记号 | 5 档力度 + 1 处渐强 |
| `pedal_channels.mid` | 全通道一起补 | 只补通道 0 的那 1 个音 |

## 弯音范围不是全局一个数

`0xB0` 的 RPN `0x0000`（Pitch Bend Sensitivity）决定弯音轮推到底是几个半音。
MIDI 规范里它是**每通道**、而且**可以中途改**的：主音轨设 ±12 做大滑音、伴奏轨
保持默认 ±2 做颤音，是最普通的编曲。旧实现把它存成一个全局 `double`，于是：

* 最后一个 RPN 覆盖全曲所有通道：伴奏轨的 2 半音颤音被放大成 12 半音，音高错一个八度；
* 中途改范围会倒灌到它之前的弯音：前一段明明是 ±12，转出来却按后一段的 ±2 算。

现在解析阶段把 RPN 状态按通道记录（跨轨沿用，因为 setup 轨常放在文件末尾），
每次设定记成 `BendRangePoint{tick, channel, semitones, seq}`；所有轨读完之后再按
`(通道, tick)` 给每个 `PitchBendPoint` 解算出自己的 `range`。文本、HTML、MusicXML
以及滑音 / 颤音判定四处一律读 `pb.range`。`CC38`（Data Entry LSB）的音分微调
也一并支持（12 半音 + 50 音分 = 12.5）。

| 素材 | 场景 | 旧版 | 现在 |
| --- | --- | --- | --- |
| `bendrange_channels.mid` | 通道 0 ±12、通道 1 默认 ±2 | C5 / C5 | C5 / D4 |
| `bendrange_timeline.mid` | 同通道 0 tick ±12 → 960 tick ±2 | D4 / D4 | C5 / D4 |
| `bendrange_crosstrack.mid` | RPN 写在末尾 setup 轨 | C5 | C5（防回归） |

CLI 与 HTML 页眉写明 `弯音范围：±2 / ±12 半音，按通道与时间生效（2 处设定，1 条通道）`，
网页文件面板走新导出 `_midi2jianpu_bend_range_info`。`MidiData::bendRange` 保留为
「文件里没有任何 RPN 时的默认值」，不再参与谱面计算。

## 省略的状态字节不是坏文件

MIDI 为了省字节允许「省略状态字节」：连续同类事件只写一次 `0x90`，后面直接跟
音高 / 力度，这叫 running status。但它有严格的生命周期：

* 只有**通道消息**（`0x80`–`0xEF`）能建立 running status；
* **meta / SysEx / System Common**（`0xFF` / `0xF0` / `0xF7` / `0xF1`–`0xF6`）之后取消；
* **System Real-Time**（`0xF8`–`0xFE`，MIDI clock、active sensing）不改变它。

旧实现把读到的每个状态字节都记成 running status。于是歌词 `0xFF` 之后再出现
省略状态字节的音符时，音高 `62` 被读成 meta 类型、力度 `100` 被读成 meta 长度，
事件流从那里整体错位——一句歌词之后半首曲子的音符全丢。

现在按规范分三类处理，并且对「系统事件之后仍省略状态字节」的老导出器留了
宽容兜底：按**上一条通道状态**补回。补回的状态决定该读几个数据字节
（`0x90` 两个、`0xC0` 一个），不会多吃少吃了让后面的音符继续错位，也不会把
补回的音符错记到通道 0。CLI 页眉、HTML 页眉、网页文件面板同步写明补回几处，
新导出 `_midi2jianpu_running_status_info`。严格按规范重写状态字节的文件不会
触发补回，输出与旧版逐字节一致。

| 素材 | 场景 | 旧版 | 现在 |
| --- | --- | --- | --- |
| `running_meta.mid` | 歌词 meta 后省略状态字节 | 只有 C4 | C4 / D4 |
| `running_sysex.mid` | SysEx 后省略状态字节 | 只有 C4 | C4 / D4 |
| `running_realtime.mid` | 音符流中插入 `0xF8` 时钟 | 只有 C4 | C4 / D4（且无需补回） |
| `running_standard.mid` | meta 后规规矩矩重写状态字节 | C4 / D4 | C4 / D4（防回归） |

## 文件被截断时不要读到 buffer 外面

浏览器里最容易碰到的坏文件是「下载到一半的 `.mid`」：`MThd` / `MTrk` 头都在，
长度字段还写着原值，数据却少了几十字节。旧解析器只在 SysEx 分支用
`min(trkEnd, size)` 夹过一次，meta 分支只夹到 `trkEnd`（它本身可能已经越过
文件末尾），通道消息分支更是直接 `d[pos++]` 不检查。于是解析器会越过 buffer
末尾，把堆里相邻内存当成 delta / 状态字节继续解析下去。

探针里一份只有 2 个音的截断 MIDI 被读出 **10 个幻影音符**，调性从 `1=F` 被
带偏成 `1=Eb`；另一份被截断的 `0x05` lyric meta 冒出 **9 个乱码歌词音节**，
还顺带触发了一次「省略状态字节补回」。WASM 里同样会读到线性内存里相邻的堆块。

现在每条轨开头统一取 `hardEnd = min(trkEnd, size)`，内层事件循环、VLQ、固定
长度通道消息、meta 与 SysEx 全用这一个硬边界：读任何数据字节之前先确认剩余
长度，不够就**停在本轨、保留此前读完的完整事件**，残片整条丢弃。CLI / HTML
页眉 / 网页文件面板都会写明「文件数据不完整：N 条轨道在声明结尾前被截断，已按
实际字节生成谱面（丢弃 M 个不完整事件）」，用户不会把缺失的后半首当成转换器
漏掉了小节。

| 素材 | 场景 | 旧版 | 现在 |
| --- | --- | --- | --- |
| `truncated.mid` | 长度声明 +200，轨尾只剩半个 note-on | 10 个音、调性被带偏 | 2 个音 + 页眉告警 |

合法文件的 `trkEnd` 恒等于可用字节，所有新检查都不会触发：68 份既有素材与真实
人声曲目的 txt / HTML / MusicXML 逐字节零差异。

## 端口不是注释：FF 21 与 FF 20

SMF 里 `FF 21 01 pp` 是 **MIDI Port / Cable Number**，指定本轨后续事件送往哪个
端口；`FF 20 01 cc` 是 **Channel Prefix**，指定其后的 meta / SysEx 关联到哪个
通道。端口号是 `(port, channel)` 二元组的一半：port 0 ch0 与 port 1 ch0 是两台
设备上的两件乐器，踏板、弯音范围、力度、GM 音色都不能互相串。

旧实现只读状态字节低 4 位的通道号，两类 meta 都当普通字节跳过：

| 素材 | 场景 | 旧版 | 现在 |
| --- | --- | --- | --- |
| `port_pedal.mid` | port 0 ch0 踩踏板、port 1 ch0 不踩 | 3 个音全被补长 | 只补长 port 0 的 2 个音 |
| `port_bend.mid` | port 0 设 RPN ±12、port 1 默认 ±2 | C5 / D5 | C5 / E4 |
| `port_prefix.mid` / `port_prefix_base.mid` | 写 / 不写 FF 20 | — | 谱面正文逐字符一致 |
| `port_standard.mid` | 全程不写端口声明 | 与旧版一致 | 与旧版一致（防回归） |

现在把逻辑通道编码成 `port * 16 + ch`，端口**不跨轨继承**（轨首重置为 0，
所以 `port_pedal.mid` 里第三条没写 `FF 21` 的轨仍归 port 0）。`port 0` 时编码
值与旧值完全相同，没有端口声明的文件三层输出逐字节零回归。`FF 20` 按规范
只记数、不重定向通道消息——把它当通道号会把 port 0 ch0 的旋律错记成 ch2
的乐器。鼓轨判定仍看低 4 位（任何端口上的 ch9 都是打击乐）。

CLI 页眉、HTML 页眉、网页文件面板同步写明端口数与隔离结果，新导出
`_midi2jianpu_port_info`。

## SysEx 不是噪音：GS/XG 的鼓模式

SMF 里 `0xF0` SysEx 常被当成「按长度跳过就行」的噪音，但 Roland GS 与
Yamaha XG 的编曲设定就写在里面：

* `F0 41 10 42 12 40 1n 15 mm cs F7`：GS「Use for Rhythm Part」，把 part `n`
  设成节奏声部（`mm≠0`）；
* `F0 43 10 4C 08 pp 07 mm F7`：XG「Part Mode」，作用相同；
* `F0 7E 7F 09 01 F7` / GS Reset / XG System On：把整台音源恢复默认
  （只有通道 10 是鼓）。

旧实现只按「通道 9 是打击乐」硬判定，于是 GS/XG 文件里被 SysEx 设成鼓的
part 会被当成旋律：鼓件音高 36 / 38 / 42 转出一串 `1,, 2,, #4,,` 低音垃圾，
还会因为音符最多抢走旋律轨身份，调性识别跟着跑偏。

现在鼓判定统一延后到所有轨读完，按 **(逻辑通道, tick)** 建时间轴：默认状态
仍是「通道 10 是鼓」，SysEx 设定可以把它改回普通乐器，Reset 把已知通道写回
默认。设定常写在文件末尾的 setup / conductor 轨上（tick 却是 0），所以按
(tick, 文件顺序) 排序后统一套用，解析顺序不再决定时间顺序；`FF 21` 端口也
参与逻辑通道编码，port 1 的 ch0 设鼓不会影响 port 0。不相干的 SysEx 一律
不动，没有这类设定的文件三层输出逐字节零回归。

| 素材 | 场景 | 旧版 | 现在 |
| --- | --- | --- | --- |
| `sysex_gs_drum.mid` / `sysex_xg_drum.mid` | GS / XG 把 ch0 设成鼓 | 8 个鼓件音变成假旋律 | 只留 8 个旋律音 |
| `sysex_gs_normal.mid` | `mode=0` 普通乐器 | 16 个音 | 16 个音（防回归） |
| `sysex_gs_reset.mid` / `sysex_gm_reset.mid` / `sysex_xg_reset.mid` | 中途发三种 Reset | 8 个鼓件音全变旋律 | 前 4 个丢、后 4 个恢复普通乐器 |
| `sysex_conductor.mid` | SysEx 写在最后一条轨 | 8 个鼓件音全变旋律 | 8 个鼓件音丢掉 |
| `sysex_ch9_normal.mid` / `sysex_ch9_drum.mid` | 通道 10 改回钢琴 / 设回鼓 | 8 个旋律音全丢 | 16 个音全留 / 8 个音丢掉 |
| `sysex_unknown.mid` | 不相干的 SysEx | 16 个音 | 16 个音（防回归） |
| `sysex_port_drum.mid` | port 1 ch0 设鼓 | 4 个鼓件音变旋律 | 只留 port 0 的 4 个音 |

## Bank Select 不是噪音：XG 鼓组库与音色时间轴

`0xB0` 的 **CC0 Bank Select MSB / CC32 Bank Select LSB** 过去和多数控制器一样被
当成「跳过两个字节」，但 Yamaha XG 正是用 `Bn 00 7F`（MSB 127）把任意 part 切成
鼓组——这是与 GS/XG SysEx Part Mode 并列的另一条常见路径。与此同时 `0xC0`
Program Change 只往 `channelProgram[channel]` 写最后一个音色号，于是前半首钢琴、
后半首小提琴的曲子，声部会被整首标成「小提琴」。

现在解析时只收集原始事件（CC0 / CC32 / `0xC0` / GM-GS-XG Reset），所有轨读完后
按 `(tick, 文件顺序)` 统一重放状态机：Bank MSB 127 且随后有 Program Change 时该
逻辑通道切为鼓，改回其他库或收到 Reset 时恢复；只有预备的 CC0、没有 Program
Change 不切鼓，通道 10 也不会被普通音色设定从鼓改回旋律。重放同时产出
`programTimeline`，`programAt(通道, tick)` 让 `listParts` 与 MusicXML 按声部首音
时刻取音色。普通 GM 文件没有 CC0 / CC32，`bankLabel()` 返回空串，三层页眉逐字节不变。

| 素材 | 场景 | 旧版 | 现在 |
| --- | --- | --- | --- |
| `bank_xg_drum.mid` | CC0=127 把 ch0 设成 XG 鼓组 | 8 个鼓件音变假旋律、多一条假声部 | 只留 8 个旋律音 |
| `bank_normal.mid` | CC0=0 普通音色库 | 16 个音 | 16 个音（防回归） |
| `bank_switch_back.mid` | tick 960 把 CC0 改回 0 | 16 个音里混着 4 个鼓件音 | 12 个音，前 4 个鼓件丢掉 |

## 为什么开源

中文简谱是中国特有的记谱体系，国外打谱软件（MuseScore、Finale）对它支持很差，国内又一直缺少一个干净的、可二次开发的基础库。这个项目想把「MIDI → 简谱」这层地基打好，让后来的人不用重复造轮子。

## 仓库维护约定（换电脑 / 绿色复制）

这个仓库只有一位维护者。GitHub 首页的 Contributors 不只按 commit author 统计，还会解析提交信息里的 `Co-Authored-By: Name <email>` 自动追加贡献者；2026-11 曾因 AI 工具自动追加的一行署名，重写了 39 个提交、21 个 tag，并切换默认分支才把 GitHub 服务端那份只增不减的统计缓存刷新掉。为杜绝复发，仓库自带三层守护：

1. **身份锁在仓库本地**：`user.name` / `user.email` / `core.hooksPath=.githooks` 写在 `.git/config` 里，随整个任务目录绿色复制，不依赖任何一台机器的全局 git 配置。
2. **提交当场拦截**：`.githooks/commit-msg` 调用 `tools/check_commit_attribution.py --file`，拦下 AI 署名行、AI 厂商邮箱以及非本人的 author/committer 邮箱。
3. **服务端兜底**：`.github/workflows/commit-guard.yml` 在每次 push 后扫描 `HEAD` 可达的全部提交，`--no-verify` 或换机器忘装钩子也绕不过去。

换电脑、换办公环境或整体复制目录之后，在仓库里跑一次即可：

```bash
python tools/setup_repo_guard.py     # Windows 也可双击 tools/setup_repo_guard.cmd
```

它只写 `.git/config`，不改全局配置、不改历史、可重复运行；日常自查用 `python tools/check_commit_attribution.py --history`。提交信息里不要放任何自动生成的署名行，也不要用 `--no-verify`。

三个 Windows 一键编译脚本（`build/*.cmd`）也已纳入版本控制，并改成从脚本自身位置
回到仓库根、不再写死本机路径；换电脑若 MSVC / emsdk 装在别处，先 `set VCT`、
`set SDK`、`set SDKV` 或 `set EMSDK` 覆盖即可，细节见 [BUILD.md](BUILD.md)。

## 贡献

Issue / PR 都欢迎。尤其欢迎：

- 真实 MIDI 样本（钢琴、民乐、电子琴录制）
- 简谱排版规范与视觉校验
- 各调式换算测试用例
- 和弦检测算法优化

提交前请跑一遍：

```bash
cd build && ctest --output-on-failure                  # 654 项单元测试
python tests/smoke.py build/Release/midi2jianpu.exe    # 端到端冒烟（含鼓轨场景）
node tests/wasm_smoke.mjs                              # WASM 产物与源码是否同步（含版本号）
python tests/check_wasm_exports.py                     # WASM 导出清单五处一致性
python tests/check_wasm_sync.py --self-test             # WASM 产物同步守护自测
```

推送后 `.github/workflows/ci.yml` 还会在 Ubuntu 上再跑一遍两个 job：CMake 编译 + 654 项单测 + 64 组 CLI 冒烟 + 72 份素材可复现校验，以及 39 组 WASM 冒烟 + 导出清单守护 + 产物同步守护。`docs/wasm/` 漏重编会让 CI 直接变红。

产物同步守护是纯 git 检查（`tests/check_wasm_sync.py`）：`wasm_smoke.mjs` 第 34 组只比对 `version.hpp` 与 wasm 页脚版本，若有人**改了 `src/` 却不升版本、也不重编**，页脚仍然「一致」，那道守护会静默放过。同步守护直接看本次提交动了哪些文件：`src/**`、`include/**`、`cmake/**`、`CMakeLists.txt`、`build/build_wasm.cmd` 里只要有一个变更，`docs/wasm/midi2jianpu.wasm` 就必须一起变；胶水层 `.js` 单独变也不行。只改测试 / 文档 / CI 配置不要求重编。
自 v1.41.0 起还加了一条**反向规则**：`.wasm` 变了（说明重编过）却没动
`version.hpp`，同样报红——否则源码改了、产物也重编了，页脚版本与源码依旧
「一致」，第 34 组照样放行，线上却拿到一个没有版本号的二进制。极少数纯产物
补提交用 `--allow-artifact-only` 显式放行，自测覆盖 16 组情形。
